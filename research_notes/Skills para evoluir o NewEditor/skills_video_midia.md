## 1. Remotion: existem Agent Skills oficiais? O que cobrem? A abordagem Remotion (ou suas skills) é melhor que o headless Chrome atual do NewEditor? Licenciamento para empresas

### Takeaway
Sim: a Remotion publica oficialmente `remotion-dev/skills` (12 skills, versão 4.0.534, repo ativo), mas o Remotion é *source-available* com licença paga para empresas com 4+ pessoas e, para "video editors / automated pipelines", cai no plano **Automators ($0,01/render, mínimo $100/mês, telemetria obrigatória no 5.0)** — atrito direto com a premissa "sem dependências pagas". O concorrente **HyperFrames (HeyGen, Apache-2.0, 60k★)** usa exatamente a mesma arquitetura do NewEditor (HTML/CSS + headless Chrome + FFmpeg, seek determinístico) e traz 21 skills — é o melhor "doador" de técnicas/skills para as camadas de motion/lettering, sem custo de licença.

### Inferences
- O NewEditor **já tem** a arquitetura Remotion/HyperFrames (headless Chrome por frame + FFmpeg). Migrar para Remotion traria React + bundler + licença Automators (custo por render e telemetria obrigatória no 5.0) sem ganho arquitetural; a recomendação é **não adotar Remotion como runtime**, mas **ler** `remotion-markup`/`remotion-captions` como checklist de boas práticas (fps de uma única fonte, premount, legendas e vídeo no mesmo grupo de trim, tipo `Caption` em JSON).
- HyperFrames é o candidato mais forte para (a) roubar padrões de "seek-safe" (adapters CSS/WAAPI/GSAP/Lottie que pausam e posicionam a animação em t), (b) usar `frame.md`/`design.md` como formato da biblioteca de referências em Markdown do NewEditor, (c) usar `/embedded-captions` e `/talking-head-recut` como referência de lettering na posição de legenda, e (d) eventualmente trocar a captura própria por `@hyperframes/engine` (Puppeteer vs. playwright-core atual — avaliar). Licença Apache-2.0 permite embutir no produto.
- Se o NewEditor fizer preview/edição no browser com WebCodecs, Mediabunny (MPL-2.0, independente do Remotion) é uma peça reutilizável sem a licença Remotion; MPL-2.0 exige publicar alterações nos *arquivos* da lib, não no produto todo.
- Atenção ao uso de GSAP: se o NewEditor oferecer ao usuário final um editor visual de animações, isso pode cair na cláusula anti-concorrência da licença GSAP; usar WAAPI/CSS puros evita o risco.

### Gaps
- Não consegui ler o componente de preços renderizado nem o PR #3750 com as mudanças exatas da licença 5.0 (GitHub retornou 503 na página; li o LICENSE.md bruto).
- Não há benchmark público HyperFrames vs. renderer próprio do NewEditor; precisa medir no M5 Pro.
- Não verifiquei se o HyperFrames envia telemetria por padrão.

## 2. FFmpeg skills/MCPs, auto-edição (silêncio/jump-cut), transcrição/diarização (Apple Silicon), legendas, loudness/áudio, cor/LUT, detecção de cena, B-roll/stock e "copy to image"

### Takeaway
O ecossistema mais útil para o NewEditor não são os "FFmpeg MCPs" genéricos, e sim (1) skills que codificam **regras de corte** (video-use: 12 hard rules; auto-editor: thresholds/margens), (2) ASR local com timestamps por palavra em PT (WhisperX com alinhador wav2vec2-PT, whisper.cpp com Metal/Core ML, Parakeet v3 com PT e CC-BY-4.0), (3) servidores "guardrailed" como o **Kinocut/mcp-video** (Apache-2.0, 203 tools, quality gates de LUFS/blackdetect). Vários itens populares dependem de API paga (video-use→ElevenLabs; claude-video→Veo/Gemini) ou de pesos não comerciais (CrisperWhisper) — usar só as técnicas.

## 3. DaVinci Resolve / Premiere / After Effects / CapCut: o que existe e como usar (round-trip, extração de referências)

### Takeaway
O Resolve é o alvo mais maduro: **Resolve Studio 21.1 tem MCP nativo oficial** (Claude/Claude Code/Codex) e o MCP comunitário `samuelgursky/davinci-resolve-mcp` (MIT, 3,4k★, 389 tools, edição offline de .drp/.drx). ## 4. Skills de estratégia de conteúdo short-form / retenção (hooks, pattern interrupts, ritmo) para alimentar as regras de edição

### Takeaway
Existem poucas skills sérias; a mais estruturada é `iart-ai/tiktok-video-skills/short-form-video` (MIT), que codifica contrato de retenção (uma ideia, loop aberto nos 3 s, hook em texto no frame 1, interrupções a cada ~2–4 s com intervalos irregulares, punch-in de 112%). Os números de retenção citados nessas skills **não têm fonte** — usar como heurística, não como verdade. As regras mais acionáveis para o NewEditor vêm de video-use (corte) e do aviso do MCP do Resolve de que "o take menos fluente muitas vezes é o melhor".

### Cited Findings
- `iart-ai/tiktok-video-skills` (MIT): skills `short-form-video`, `caption-animation`, `countdown-video`, `lower-thirds`; instala com `npx skills add iart-ai/tiktok-video-skills` ou como plugin marketplace; parte de 14 pacotes (youtube-video, kinetic-typography, motion-design, explainer-video, manim, etc.); empresa iart.ai vende o agente completo — [README tiktok-video-skills](https://github.com/iart-ai/tiktok-video-skills)
- Conteúdo de `short-form-video` (v0.1.0): "One idea per video"; "Open a loop in the first ~3s, close it last"; "No dead air"; arco de 20 s (Hook 0–1 s, Setup 1–4 s, Body 4–17 s, Payoff/loop 17–20 s; escalar o corpo, nunca o hook); 4 tipos de hook (open loop, promessa direta, pattern interrupt, negação); hook "on-screen as text by frame 1 (85% watch muted)"; "visual change every ~2–4 seconds"; "a metronome reads as boredom; uneven cuts read as momentum"; punch-in com spring até 112%; loops casando último e primeiro frame; safe areas 9:16 — [SKILL.md short-form-video](https://github.com/iart-ai/tiktok-video-skills/blob/main/skills/short-form-video/SKILL.md)
- A mesma skill afirma (sem fonte): ~87% decidem em 3 s; limiar de ~70% de view-through (Shorts ~73%, TikTok ~78%, Reels ~65%); interrupção a cada 4 s retém ~58% vs ~41% — **estatísticas não verificadas** — [SKILL.md short-form-video](https://github.com/iart-ai/tiktok-video-skills/blob/main/skills/short-form-video/SKILL.md)
- **Video Editing Pro** (comunidade): talking-head short-form — seleção de frases-hook, "scoring sentence value", limiares de pausa com precisão de ms, limpeza seletiva de fillers, "dynamic energy curves"; repo de origem não verificado — [claudskills](https://claudskills.com/skills/video-editing-pro/); [mcpmarket](https://mcpmarket.com/tools/skills/video-editing-pro)
- **viral-video-hooks-retention** (josiahsiegel): 56 instalações, ~50★; cita "8.25 seconds attention span" sem origem clara — [skillselion](https://skillselion.com/skills/josiahsiegel/claude-plugin-marketplace/viral-video-hooks-retention)
- video-use: processo "Ask → confirm → execute → self-eval → persist"; brief de sub-agente editor para escolher o melhor take por *beat* (preferir silêncios ≥400 ms; manter deslizes inevitáveis se não houver take melhor, anotando o motivo); sub-agente crítico "to roast, not to praise" com problemas ranqueados por timecode; "animation payoff timing": iniciar a revelação `reveal_duration` antes da palavra-chave para o frame final coincidir com a fala; nunca revelar dois elementos independentes ao mesmo tempo; nunca easing linear — [SKILL.md video-use](https://github.com/browser-use/video-use/blob/main/SKILL.md)
- MCP do Resolve (samuelgursky): "Choosing the best take" está explicitamente fora de escopo — ranking por fluência não mede performance; defaults "generous" porque recuperar material descartado é lento e invisível — [README davinci-resolve-mcp](https://github.com/samuelgursky/davinci-resolve-mcp)
- OpenMontage "Paste a video": agente analisa transcrição, ritmo, cenas, keyframes e estilo de um Short/Reel/TikTok de referência e gera plano de produção — [README OpenMontage](https://github.com/calesthio/openmontage)

### Inferences
- Regras diretamente traduzíveis para o motor de edição do NewEditor: (1) hook textual no frame 1 (o lettering automático já existe — garantir que aparece no 1º frame dos shorts); (2) "pattern interrupt budget" com intervalos irregulares de 2–4 s usando punch-in digital (zoom 1,08–1,12x com spring) quando não houver B-roll; (3) nunca fade-in de preto no short; (4) payoff de motion sincronizado com timestamp da palavra; (5) loop: último frame ≈ primeiro.
- O alerta do MCP do Resolve sugere que a decupagem do NewEditor deve **sinalizar** retakes/hesitações com score em vez de cortar cegamente, e deixar margem "generosa" para a revisão humana — alinhado ao fluxo "edita automático → humano revisa".
- O Thales já tem skills próprias (`qc-analista-de-retencao`, `editor-sistema-editorial`, `diretor-narrativo`) no ambiente; as skills públicas acima servem mais como checklist complementar do que como substitutas.

### Gaps
- Não encontrei estudos primários (YouTube/TikTok/Meta) que confirmem os números de retenção usados nessas skills.
- Nenhuma skill encontrada é específica para PT-BR ou para o mercado brasileiro.

## 5. Skills de motion graphics/animação (Lottie, GSAP, CSS, Rive, Manim) e de pixel-art/sprites

### Takeaway
Para motion determinístico em HTML, as melhores fontes de técnica são as skills do **HyperFrames** (animação/keyframes seek-safe com adapters GSAP/Lottie/CSS/WAAPI) e do **Remotion** (frame-driven). Lottie ganhou relevância extra porque o **Resolve 21 importa Lottie nativamente**, e existe `diffusionstudio/lottie` (text-to-lottie). Manim tem várias skills comunitárias e é MIT. ### Inferences
- Para o NewEditor, o mais valioso é padronizar **um contrato de seek** (ex.: `window.seek(t)` / `goToTime(ms)` estilo OGraf) e suportar múltiplos runtimes por adapter, como o HyperFrames — assim a biblioteca de referências pode conter animações CSS/WAAPI, GSAP ou Lottie e todas renderizam frame-exato no headless Chrome e no preview WebGL2.
- Lottie é estratégico: (a) roda no Chrome via lottie-web com `goToAndStop(frame, true)` — seekável; (b) agora é importável nativamente no Resolve 21 para revisão/finalização; (c) `text-to-lottie` pode gerar ícones/elementos animados da biblioteca de motion narrativo sem API paga.
- Manim serve para motion "explicativo" (diagramas, equações, gráficos) como gerador offline de clipes com alpha; é Python/MIT e pode virar um "renderer plugin" do motor de motion narrativo.
- Avatar pixel-art: usar pixel-mcp/aseprite-mcp **em tempo de desenvolvimento** para produzir spritesheets (idle, fala/visemas, reações) e o NewEditor só consome PNG/spritesheet + JSON de frames (sem Aseprite no runtime). Aseprite é vendido comercialmente e tem licença própria (verificar EULA/preço em aseprite.org); LibreSprite seria a alternativa livre, mas os MCPs citados miram o Aseprite.
