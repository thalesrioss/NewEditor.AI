# Instale pouco, copie técnicas, blinde o produto

Nenhuma skill, plugin ou MCP pronto resolve a parte difícil do NewEditor.AI: ninguém publicou decupagem em PT-BR com revisão humana, teste golden de mídia nem sincronia labial de avatar a partir do ASR, e o ganho real vem de três movimentos baratos, nesta ordem. **O primeiro é tirar o `@anthropic-ai/sdk` do caminho padrão do servidor**, porque ele continua declarado em `apps/server/package.json` (`^0.133.0`) e é importado estaticamente em quatro arquivos, inclusive `decupagem/decide.ts`, embora o cérebro padrão seja o local. **O segundo é instalar uma leva pequena de plugins oficiais de desenvolvimento** (hookify, typescript-lsp, frontend-design, playground, claude-md-management e claude-code-setup) mais as evals-skills de Hamel Husain e Shreya Shankar, e passar a usar o que já está habilitado e é gratuito: `/run-skill-generator`, `/skill-doctor`, `skill-creator` e os plugins engineering, design e product-management. **O terceiro, já no produto, é copiar regras e padrões em vez de instalar runtimes**: as regras de corte do video-use (MIT), o contrato de animação seekável do HyperFrames (Apache-2.0), o auto-editor (domínio público) como oráculo de silêncio e os quality gates do Kinocut (Apache-2.0), tudo rodando sobre o mlx-whisper local que o projeto já usa. A lista do que evitar pesa tanto quanto a do que instalar: Remotion como runtime (plano Automators a US$ 0,01 por render, mínimo de US$ 100/mês), video-use como está (transcrição pela ElevenLabs, paga), código do OpenMontage (AGPL-3.0), pesos do CrisperWhisper (não comerciais), automação sobre clip.cafe (sem licença de reuso) e claude-mem. A maior oportunidade de produto não aparece em skill nenhuma: o DaVinci Resolve 21 importa OTIO/FCPXML, Lottie e gráficos HTML no padrão OGraf, o que abre uma ida e volta em que a decupagem e os letterings seekáveis do NewEditor chegam à revisão humana no Resolve sem virar um ProRes achatado.

## O SDK pago ainda é carregado junto com o cérebro local

O primeiro passo é desfazer uma contradição, sem instalar nada. O servidor já tem o interruptor certo: `apps/server/src/config.ts` define o cérebro como `'local'` a menos que `NEWEDITOR_BRAIN=claude`, e o log de boot anuncia "local (sem API)". Mesmo assim, **o SDK continua declarado e é importado estaticamente em `llm.ts`, `index.ts`, `agent.ts` (`betaZodTool`) e `decupagem/decide.ts` (`betaZodOutputFormat`)**, conforme verifiquei no código local em 10/out/2026. Na prática, o módulo de decupagem carrega o SDK mesmo no modo local.

Isso tem dois efeitos no desenvolvimento. O Claude Code traz a skill embutida `claude-api`, que **"activates automatically when your code imports `anthropic` or `@anthropic-ai/sdk`"** ([Claude Code Docs](https://code.claude.com/docs/en/commands)), de modo que toda sessão que tocar a decupagem vai puxar o agente para padrões de API paga, como prompt caching, managed agents e migração de modelo. Além disso, quem ler o código, humano ou agente, vai concluir que o Claude é o cérebro "natural" do produto.

A correção é pequena e merece um ADR escrito com a skill `engineering:architecture`, que já está habilitada. Ela consiste em trocar os helpers `betaZod*` por schemas zod puros, mover o provedor Claude para um pacote opcional carregado por `import()` dinâmico só quando `NEWEDITOR_BRAIN=claude` (ou removê-lo de vez) e travar a regressão com uma regra do hookify que avisa quando código de produto importar o SDK. Para silenciar a skill neste repositório, as skills embutidas podem ser ocultadas uma a uma com `skillOverrides` ([Claude Code Docs](https://code.claude.com/docs/en/skills)). Pelo mesmo motivo, o plugin oficial `agent-sdk-dev` fica de fora: ele serve para construir apps sobre o Agent SDK, que pressupõe a API da Anthropic.

## Metade do kit já está habilitada e não custa nada

Antes de abrir o marketplace, vale aproveitar o que já está na máquina. No Claude Code 2.1.292, **`/run-skill-generator`** grava em `.claude/skills/run-<nome>/` a receita para subir o app, e é essa receita que faz `/run` e `/verify` funcionarem sempre ([Claude Code Docs](https://code.claude.com/docs/en/skills)). No NewEditor, ela precisa cobrir o Vite na porta 5173, o Fastify em `NEWEDITOR_PORT` (4310 por padrão) e o `services/asr`. Os outros comandos embutidos que valem para o dia a dia são estes ([Claude Code Docs](https://code.claude.com/docs/en/commands)): `/simplify` roda quatro agentes em paralelo (reuso, simplificação, eficiência e nível de abstração); `/code-review medium --fix` procura bugs no diff local e já aplica as correções; `/skill-doctor` mostra quanto contexto cada skill consome; e `/fewer-permission-prompts` gera uma allowlist de permissões.

Três recursos estão travados porque **o branch `main` ainda não tem nenhum commit, não há remote e o `gh` não está instalado**. O `/security-review` "needs an `origin` remote", o `/batch` precisa de git e o plugin `code-review` exige `gh` autenticado e um PR aberto ([Claude Code Docs](https://code.claude.com/docs/en/commands); [README code-review](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/code-review/README.md)). O commit inicial é decisão sua, já que a regra do projeto é não commitar sem pedido.

Na conta claude.ai, os plugins oficiais engineering, design e product-management já estão habilitados e funcionam sem conector nenhum: o `write-spec` diz literalmente que, sem ferramentas conectadas, deve "work entirely from what the user provides" ([write-spec](https://github.com/anthropics/knowledge-work-plugins/blob/main/product-management/skills/write-spec/SKILL.md)). ## Seis plugins oficiais formam a primeira leva de instalação

Para um fundador solo, os plugins oficiais que mais rendem são os que trabalham sozinhos, sem exigir disciplina extra. O **hookify** transforma regras de memória em travas reais: as regras são arquivos `.claude/hookify.*.local.md`, com YAML e regex, e valem sem reiniciar ([README hookify](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/hookify/README.md)). Quatro regras já pagam a instalação no primeiro dia: bloquear edição no projeto *ground truth* `prj_mv1tcs9p1vslt`, bloquear `rm -rf` em `/Volumes/Thales SSD`, avisar quando código de produto importar `@anthropic-ai/sdk` e avisar sobre `git commit` ou `git push` sem pedido explícito.

O **typescript-lsp** dá navegação semântica no monorepo (core, server e web), mas depende de um binário que **ainda não está instalado**: `which typescript-language-server` não encontra nada ([README typescript-lsp](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/typescript-lsp/README.md)). O **frontend-design**, atualizado em 3/set/2026, afasta a UI do Editor Brain e do Kanban dos padrões genéricos: pede de 4 a 6 cores nomeadas, tipografia com personalidade e um único momento de motion orquestrado em vez de animações espalhadas, com foco visível e reduced-motion como piso de qualidade ([SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md)). O **playground** gera um HTML de arquivo único com controles, preview ao vivo e um prompt pronto para copiar ([README playground](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/playground/README.md)). É o jeito mais rápido de calibrar estilos de legenda e lettering, curvas de ducking, limiares de silêncio e padding da decupagem, e devolver valores exatos ao Claude. O **claude-md-management** mantém a memória do projeto em dia (portas, benchmarks, projeto intocável) com `claude-md-improver` e `/revise-claude-md` ([README](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/claude-md-management/README.md)). O **claude-code-setup** faz um diagnóstico somente leitura e recomenda uma ou duas automações por categoria ([README](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/claude-code-setup/README.md)).

```bash
# Claude Code (no app desktop: + > Plugins > Add plugin)
/plugin marketplace add anthropics/claude-plugins-official   # só se o marketplace oficial não aparecer
npm install -g typescript-language-server typescript
/plugin install hookify@claude-plugins-official              # escopo project: as regras são deste repo
/plugin install typescript-lsp@claude-plugins-official
/plugin install frontend-design@claude-plugins-official
/plugin install playground@claude-plugins-official
/plugin install claude-md-management@claude-plugins-official
/plugin install claude-code-setup@claude-plugins-official
```

O marketplace oficial só é adicionado automaticamente na primeira sessão interativa de terminal ([docs](https://code.claude.com/docs/en/plugins/anthropic-marketplaces)). Como o `known_marketplaces.json` local não o lista, a primeira linha provavelmente será necessária.

## No produto, copie as regras de corte e use o ASR local que já existe

O texto técnico mais útil para a decupagem é o `SKILL.md` do **video-use** (browser-use, MIT). Ele **não deve ser instalado como está**, porque a transcrição depende da ElevenLabs Scribe com `ELEVENLABS_API_KEY` ([README video-use](https://github.com/browser-use/video-use)). As regras, porém, são ouro e podem virar testes ou linters do motor de corte ([SKILL.md video-use](https://github.com/browser-use/video-use/blob/main/SKILL.md)). Elas pedem padding de 30 a 200 ms em volta de cada corte, porque os timestamps de ASR derivam de 50 a 100 ms, e proíbem cortar dentro de uma palavra. Silêncios de 400 ms ou mais são os cortes mais limpos; entre 150 e 400 ms, o corte só vale com checagem visual, e abaixo de 150 ms é inseguro. Toda borda leva fade de 30 ms, as legendas entram por último na cadeia de filtros e o loudness é medido com `ebur128=peak=true`. A arquitetura também serve para a tela de revisão humana e para o cérebro local: o LLM "never watches the video. It reads it", recebendo transcrições por palavra empacotadas em cerca de 12 KB e abrindo um filmstrip com waveform só nos pontos de decisão.

Duas fontes complementam o video-use. O **auto-editor** (5,5 mil estrelas, domínio público, com skill oficial instalável via `npx skills add WyattBlue/auto-editor`) tem limiar padrão `audio:threshold=0.04`, margem de 0,2 s e exporta para Premiere, Resolve e Final Cut ([GitHub](https://github.com/WyattBlue/auto-editor)); serve como oráculo de silêncio no `npm run bench` e como exportador XML para a revisão. O **Kinocut**, ex-mcp-video (Apache-2.0), contribui com quality gates pós-render (blackdetect, LUFS e inspeção dos primeiros 15 s) e com um fluxo de cor em que um plano-herói serve de referência para os demais ([README Kinocut](https://github.com/KyaniteLabs/mcp-video)). Copie o desenho dos gates e só instale o MCP num projeto de teste, porque são **203 ferramentas** entrando no contexto.

**ASR.** O `services/asr` já roda **mlx-whisper com `whisper-large-v3-turbo` e `word_timestamps=True`**, com um prompt "ao pé da letra" para preservar hesitações, conforme confirmei no código. As melhorias possíveis são incrementais e todas locais.

| Ferramenta | Licença | O que resolve | Ressalva |
|---|---|---|---|
| **WhisperX** | BSD-2 | Alinhamento por palavra com o modelo PT `jonatasgrosman/wav2vec2-large-xlsr-53-portuguese`, o que ataca a deriva de timestamp que hoje força o padding ([GitHub](https://github.com/m-bain/whisperX); [alignment.py](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py)). | Medir o ganho real sobre o mlx-whisper. |
| **pyannote community-1** | CC-BY-4.0 | Diarização de podcasts com duas vozes. | O acesso exige aceitar termos que incluem e-mails de marketing, e a identificação de falante só existe no Precision-2, que é pago ([HF](https://huggingface.co/pyannote/speaker-diarization-community-1)). |
| **Parakeet TDT 0.6B v3** | CC-BY-4.0, uso comercial liberado | Transcrição com timestamps por palavra ([HF](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)). | Treinado em português europeu: meça o WER em PT-BR antes de adotar. |

O único benchmark público de velocidade compara um clipe curto em inglês num M4 (Parakeet com 0,50 s contra 1,02 s do mlx-whisper turbo), o que não diz nada sobre falas longas em PT-BR ([mac-whisper-speedtest](https://github.com/anvanvan/mac-whisper-speedtest)). **O CrisperWhisper fica de fora**: ele transcreve hesitações e fillers literalmente, mas os pesos padrão estão sob licença Nyra Health de pesquisa não comercial ([GitHub](https://github.com/nyrahealth/CrisperWhisper)). A alternativa livre é combinar VAD, os gaps entre palavras do alinhador e uma lista de fillers em PT ("é", "tipo", "né"). Uma frase do MCP comunitário do Resolve deveria guiar o motor: **"The take that plays is regularly the least fluent one, because the hesitation is often the acting"** ([README davinci-resolve-mcp](https://github.com/samuelgursky/davinci-resolve-mcp)). Na prática, isso significa sinalizar hesitações com um score e deixar margem generosa para a revisão humana, em vez de cortar às cegas.

**Testes golden de mídia e evals.** Este é o maior buraco do ecossistema: **não existe skill pronta que compare render e referência com SSIM/PSNR mais loudness**, e o único validador encontrado tem 0 estrelas e um commit ([GitHub](https://github.com/alinaqi/demo-video-skill)). O caminho é escrever `.claude/skills/media-golden/SKILL.md`, que manda o agente rodar um `npm run test:golden` próprio. Esse script gera fixtures sintéticas com `lavfi testsrc2/sine`, compara frames com os filtros `ssim`, `psnr` e, se disponível, `libvmaf` ([FFmpeg Filters](https://ffmpeg.org/ffmpeg-filters.html)), mede loudness com `ebur128` e checa duração e sincronia com `ffprobe`. Para garantir que preview e export batem, ele também captura o canvas do preview no tempo t via Playwright e compara com o frame do FFmpeg no mesmo t.

Para avaliar a decupagem, a metodologia da Anthropic recomenda graders de código primeiro, de 20 a 50 tarefas tiradas de falhas reais e suítes separadas de capability e de regressão ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). O `npm run bench` de IoU já é exatamente esse tipo de grader. As **evals-skills** de Husain e Shankar completam o quadro ([GitHub](https://github.com/ai-evals-course/evals-skills)). A `error-discovery` monta um app de revisão em HTML servido por Python stdlib, sem dependências; apontada para um JSONL com os diffs dos `review.json`, ela agrupa as suas notas numa taxonomia de failure modes. A `write-code-eval` cria checagens por failure mode, como corte dentro de palavra, respiração cortada, silêncio residual e retake não removido. O repositório antigo `hamelsmu/evals-skills` está deprecated, então use o novo ([GitHub](https://github.com/hamelsmu/evals-skills)). Os próprios autores avisam que skills "grounded in your stack, your domain, and your data will outperform them", o que reforça escrever as suas.

## Motion e lettering já seguem o padrão que HyperFrames e o Resolve 21 adotaram

O NewEditor já renderiza como os dois principais frameworks do setor: o headless Chrome posiciona cada frame e o FFmpeg codifica. Por isso, **adotar o Remotion como runtime não traz ganho arquitetural, só custo**. O Remotion é source-available e só é gratuito para indivíduos e empresas com até 3 funcionários, limite em que agências contam também os contratados. Quem constrói "video editors, prompt-to-video tools, automated video pipelines" cai no plano **Automators, a US$ 0,01 por render com mínimo de US$ 100/mês**, e embutir o `<Player>` conta como automação. No Remotion 5.0, a telemetria passa a ser obrigatória nesse plano ([License FAQ](https://www.remotion.dev/docs/license/faq); [LICENSE.md](https://raw.githubusercontent.com/remotion-dev/remotion/main/LICENSE.md)), e o renderer client-side já envia um evento de telemetria a cada render, mesmo sem license key ([docs](https://www.remotion.dev/docs/client-side-rendering)). As skills oficiais (`npx skills add remotion-dev/skills`) servem como checklist de leitura ([GitHub](https://github.com/remotion-dev/skills)). A `remotion-markup` ensina três coisas aproveitáveis: usar uma única fonte de fps, pré-montar a mídia um segundo antes e lembrar que "CSS `transition` or `animation` will not render correctly" ([SKILL.md](https://raw.githubusercontent.com/remotion-dev/skills/main/skills/remotion-markup/SKILL.md)). A `remotion-captions` contribui com o tipo `Caption` em JSON como referência de schema.

O doador certo é o **HyperFrames** da HeyGen (60 mil estrelas, Apache-2.0, "no per-render fees or commercial-use thresholds"), que usa exatamente a arquitetura do NewEditor ([README](https://github.com/heygen-com/hyperframes/blob/main/README.md)). As skills mais úteis são `hyperframes-keyframes` e `hyperframes-animation` (adapters seekáveis para GSAP, Lottie, CSS e WAAPI), `embedded-captions` (lettering atrás do apresentador), `talking-head-recut` (lower-thirds, títulos cinéticos e pull-quotes) e `hyperframes-audio` (ducking espectral da trilha só nas bandas que a voz ocupa). Há três ressalvas: a `/media-use` e o render em nuvem podem gerar custo, a telemetria não foi verificada e as 21 skills se sobrepõem ao `claude-animation` e ao `motion-designer` que você já tem. Por isso, **copie três ou quatro SKILL.md para `.claude/skills/` do projeto em vez de instalar o plugin global**.

Dois pontos de licença completam o quadro. O **GSAP** é gratuito inclusive para uso comercial, mas a licença proíbe o uso em ferramentas no-code de animação visual que concorram com a Webflow ([GSAP Standard License](https://gsap.com/community/standard-license/)); se o NewEditor oferecer ao usuário final um editor visual de animação, prefira CSS ou WAAPI puros. O **Mediabunny** (MPL-2.0) é uma opção de toolkit WebCodecs que não exige licença do Remotion ([GitHub](https://github.com/Vanilagy/mediabunny)).

**O Resolve é a maior oportunidade, e ela não aparece em nenhuma skill.** O Resolve Studio 21.1 traz um MCP nativo para Claude e Claude Code ([Digital Production](https://digitalproduction.com/2026/09/08/resolve-21-1-adds-mcp-and-finally-gets-presets/)), e esse servidor já está na sua sessão. O Resolve 21 também passou a importar de forma nativa **gráficos HTML OGraf e animações Lottie** ([Jayaretv](https://jayaretv.com/news/davinci-resolve-21-expands-creative-horizons-with-native-lottie-and-ograf-support/)). O OGraf é uma especificação MIT da EBU: quando o gráfico declara `supportsNonRealTime`, ele precisa implementar `goToTime()` em milissegundos ([especificação](https://github.com/ebu/ograf/blob/main/v1/specification/docs/Specification.md)), o espelho exato do `window.seek(t)` do NewEditor.

O round-trip proposto funciona assim. O NewEditor exporta a decupagem em OTIO (OpenTimelineIO, Apache-2.0 — [GitHub](https://github.com/AcademySoftwareFoundation/OpenTimelineIO)) ou FCPXML, mais o SRT, com os letterings empacotados como OGraf. O Resolve importa a timeline com `ImportTimelineFromFile`, que aceita OTIO e FCPXML (dá para confirmar com `search_scripting_api` no próprio MCP), e o editor humano revisa. Por fim, o OTIO revisado volta para o NewEditor, e o diff entre o corte da máquina e o corte humano vira dado para as regras. Ainda falta validar quais recursos do OGraf o Resolve suporta de fato. No desenvolvimento, o MCP nativo também serve para gerar LUTs e compará-las com o `lut3d` do NewEditor. Ele **não pode ser dependência do produto**, porque o Studio é pago, o scripting Python virou exclusivo do Studio no 21.1 e projetos abertos no 21.1 não abrem mais no 20.3 ([README davinci-resolve-mcp](https://github.com/samuelgursky/davinci-resolve-mcp); [Digital Production](https://digitalproduction.com/2026/09/08/resolve-21-1-adds-mcp-and-finally-gets-presets/)). Os MCPs de Premiere e After Effects dependem de CEP/ExtendScript e são frágeis ([GitHub](https://github.com/ayushozha/AdobePremiereProMCP)). O CapCut não tem API pública, e os MCPs que existem editam os arquivos de draft por engenharia reversa ([GitHub](https://github.com/Atx-Guy/capcut-mcp-server)).

Para o avatar pixel-art, use o **pixel-mcp** (Go, MIT) ou o **aseprite-mcp** (104 ferramentas) só durante o desenvolvimento, para produzir spritesheets ([pixel-mcp](https://github.com/willibrandon/pixel-mcp); [aseprite-mcp](https://github.com/diivi/aseprite-mcp)). O produto consome apenas PNG e o JSON de frames, já que o Aseprite é um app comercial. Não existe skill de visemas a partir dos timestamps do ASR, então essa parte é construção interna. Para motion explicativo, o **Manim** (MIT, v0.22.0) gera clipes offline ([GitHub](https://github.com/ManimCommunity/manim)), e o **diffusionstudio/lottie** gera Lottie a partir de texto ([GitHub](https://github.com/diffusionstudio/lottie)), formato que entra direto no Resolve 21.

Para o B-roll do Cinéfilo.AI, a skill `copy-to-image`, que você já tem, cobre imagens estáticas. Para vídeo, a Pexels exige link e crédito e limita a 200 requisições por hora ([docs](https://www.pexels.com/api/documentation/)), e a Pixabay exige cache de 24 h e avisa que a API "is made for real human requests" ([docs](https://pixabay.com/api/docs/)). Por isso, um índice local de downloads curados é mais seguro que uma busca 100% automática.

**Segurança de skills de terceiros.** O risco é concreto e documentado. A Snyk analisou 3.984 skills no ClawHub e no skills.sh e encontrou **pelo menos um problema crítico em 13,4% delas** (malware, prompt injection ou segredos expostos), além de alguma falha de segurança em 36,82% ([Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub)). A Koi Security marcou **341 de 2.857 skills do ClawHub como maliciosas**, 335 delas de uma campanha que instalava o stealer de macOS AMOS por meio de "pré-requisitos" falsos ([The Hacker News](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)). O próprio Claude Code aplica o `allowed-tools` de skills de projeto mesmo em pastas nunca confiadas, e comandos `!` "never prompt for permission while the skill renders" ([Claude Code Docs](https://code.claude.com/docs/en/skills)). A Anthropic também avisa que "doesn't review third-party marketplaces" ([docs](https://code.claude.com/docs/en/plugins/anthropic-marketplaces)). O `claude-animation`, que você instalou a partir de `buildwithhanif/claude-animation-skill`, é de terceiros e merece a mesma auditoria. Antes de cada instalação, leia o SKILL.md, os scripts e o `hooks.json`, procure `curl`, `eval`, base64, acessos a `~/.ssh` e variáveis de token, copie só o SKILL.md útil para `.claude/skills/` do projeto (onde fica versionado e auditável), fixe o commit e ligue `disableSkillShellExecution` se não precisar de comandos `!`.

**Inchaço de contexto.** Esse custo é silencioso. Num caso relatado, dois plugins do mesmo marketplace carregaram as mesmas 17 skills duas vezes e desperdiçaram **cerca de 50 mil tokens** ([anthropics/skills#189](https://github.com/anthropics/skills/issues/189)). Alguns pacotes trazem muito mais do que você vai usar: o `example-skills` instala 12 skills de uma vez, o HyperFrames traz 21 e o Kinocut, 203 ferramentas MCP. Depois de cada instalação, confira o `/context` e o `claude plugin details <nome>`, que mostra os tokens sempre carregados. Marque as skills com efeito colateral com `disable-model-invocation: true`, o que tira a descrição delas do contexto ([Claude Code Docs](https://code.claude.com/docs/en/skills)).

## Conclusão

O ecossistema de skills convergiu para a arquitetura que o NewEditor já tem: a página HTML seekável renderizada por headless Chrome mais FFmpeg (o HyperFrames), o `goToTime()` da especificação OGraf e um Resolve que agora importa gráficos HTML. Isso significa que o diferencial não está em trocar o motor, e sim em dois ativos que nenhum pacote oferece. O primeiro são os dados da revisão humana, ou seja, os diffs dos `review.json` e, no futuro, os OTIO que voltarem do Resolve. O segundo são as regras de corte em PT-BR que nascem desses dados. Por isso, as skills que mais vão mover o produto são as que você vai escrever (`decupagem-regras`, `media-golden` e um eval de IoU por failure mode), medidas com a `skill-creator` que já está habilitada. Os autores das evals-skills dizem o mesmo das próprias skills: as que nascem do seu domínio vencem as genéricas.

O risco mais provável não é faltar uma skill, é sobrar. Packs sobrepostos disputam o contexto, frameworks concorrentes brigam pelo fluxo e skills de terceiros rodam com as suas permissões. Uma leva enxuta de plugins oficiais, as regras críticas em hooks e as técnicas copiadas para dentro do repositório, versionadas e auditáveis, protegem ao mesmo tempo a restrição "sem API paga" e a cadeia de suprimentos. As dúvidas que continuam abertas, como o WER do Parakeet em PT-BR, o ganho do alinhamento do WhisperX sobre o mlx-whisper e os recursos do OGraf que o Resolve aceita de fato, só se resolvem medindo no seu M5 Pro e no seu próprio material.
